# 评测说明

## 目的

改动检索、切块、提示词或模型后，用固定用例跑一遍，确认没有退化。评测集不追求覆盖所有问题，只覆盖最容易坏的三类：

- **vocab**：单词/词条查询，走结构化直查，验证“词表类文档能被精确命中”
- **knowledge**：知识点问答，走完整检索 + 生成，验证召回和引用页码
- **meta**：知识库元问题（有哪些文档、能做什么），验证路由

## 运行

```bash
# 需要服务已启动（默认 http://127.0.0.1:8000）
python backend/scripts/eval.py

# 指定服务地址 / 只跑某一类 / 只跑前几条
python backend/scripts/eval.py --base http://127.0.0.1:8010
python backend/scripts/eval.py --category vocab
python backend/scripts/eval.py --limit 5
```

脚本会先清空 QA 缓存，避免旧答案干扰；结果写到 `backend/eval/report.md`（通过率、分类统计、逐题耗时与页码）。

## 用例格式

`backend/eval/cases.json`：

```json
{
  "id": "vocab-peril",
  "category": "vocab",
  "question": "peril 是什么意思？",
  "expect": ["严重危险"],
  "page": 1
}
```

- `expect`：答案中必须出现的字符串（可多个）
- `page`：期望命中的页码（可选，用于检查引用是否落到正确页）

## 当前基线

2026-10-31 在测试实例上的结果：

| 类别 | 通过 / 总数 | 通过率 |
| --- | --- | --- |
| vocab | 12 / 12 | 100% |
| knowledge | 5 / 5 | 100% |
| meta | 1 / 1 | 100% |
| **合计** | **18 / 18** | **100%** |

词条题走结构化直查，约 0.01 秒，不消耗模型调用；知识题真实调用模型，约 1–3 秒（首次会加载本地向量模型，可能到十几秒）。

基线依赖测试文档：`知识清单.pdf`（21 页）与 `四六级核心1500词.pdf`（86 页）。换文档后页码和部分知识题需要相应调整。

## 注意

- 知识题会真实消耗 token；批量跑之前确认 Key 和额度
- 评测结果受模型版本影响，换模型后建议重跑并记录
- 这只是一种回归检查，不代表真实使用中的全部问题；新发现的坏例子应该补进 `cases.json`
